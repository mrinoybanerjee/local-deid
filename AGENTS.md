# Local DeID: instructions for the building agent

You are building a local Mac app that de-identifies a bilingual
(English/Spanish) pediatric speech-language pathologist's clinical documents.
The documents are evaluations, assessments, IFSPs, and daily notes, and the
app runs fully offline on an 8 GB MacBook Air. v1 is built (phases 1–3);
`README.md` has the status and `install.sh` installs it. The design is final
and approved.

## Read in this order

1. `SPEC.md` (v6) is **the source of truth.** If anything else disagrees with
   it, the spec wins.
2. `docs/DECISIONS.md`: every build decision since the spec, with reasons.
3. The three design reviews and the research notes (SLP identifiers and
   allow-list, Spanish rules, model licenses, legal context) are in the
   private archive repository `mrinoybanerjee/local-deid-archive`, with the
   full build history before 2026-10-12. Read them there only as needed.

## Rules

- **Simple beats clever.** Mrinoy's rule: no over-engineering. Build only
  what SPEC v6 lists for v1. Paste in, paste out: no file import or export.
- **Never change anything except the identifiers.** Edit by span only. The
  integrity check must block output on failure.
- **Never put real client data** anywhere: not in the repo, the tests, logs,
  or the brain. All test data is synthetic.
- **Offline at runtime.** No network calls, no telemetry, and model files are
  pinned by hash.
- **Licenses:** no models trained on AI4Privacy data. That excludes OpenMed's
  Spanish and multilingual fine-tunes, piiranha, and the Isotonic models. No
  GPL code in the shipped app (for example spaCy `es_core_news_lg`).
- **Code review:** before you call a phase done, run `/cr` (GPT-6.1 Sol, high
  reasoning) on it, or run `~/Codex/Tooling/Fleet/bin/codex-review.sh`
  directly. Fix the findings or explain why not.
- **Report honestly.** Report measured numbers against the SPEC section 3
  gates. Never claim a gate is met without the harness output.

## Where to start

1. Phase 1, day 1 (SPEC sections 4.7 and 8): build the memory and speed
   harness.
   - Compare OpenAI Privacy Filter as ONNX q4 against MLX 8-bit.
   - Use a 5,000-word synthetic evaluation and a 500-word daily note.
   - Measure whole-app peak memory and cold and warm latency.
2. Build the engine in the stage order of SPEC 4.3: protect, fields, rules
   (EN + ES), roster, gazetteer, Privacy Filter, merge, propagate, decide,
   render, checks.
3. Build the data (SPEC section 7):
   - Claude-generated dev data.
   - A separate gate set generated by GPT-6.1 Sol through `codex exec`.
   - A general-text stratum.
4. Build the command-line evaluation tool and report the gates per stratum.
5. Then phase 2, the menu-bar app (SPEC section 5).
